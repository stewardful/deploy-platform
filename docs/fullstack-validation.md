# 0.3 完整部署验收

2026-10-18，在本地隔离 Ubuntu 24.04 ARM64 节点验证，限制为 2 CPU、2 GiB、512 PID，systemd / cgroup v2。容器使用独立 containerd，未连接腾讯云真实服务器。

已验证：

- 新安装包启动 containerd、Agent、控制端、Web；管理 API 需要认证。
- 真实 PostgreSQL 17、Redis 7.4、Go 示例后端/前端同时运行，数据库与缓存通过 secret 文件认证，使用项目服务名连接；只有前端映射回环端口。
- 前端写入 PostgreSQL，Redis 写入并读回相同计数。
- API 停止 PostgreSQL，后端探测得到不健康 HTTP 503，日志返回 `dependency unavailable`；重新启动后恢复健康。
- 停止 Agent 并移除测试后端实例，启动 Agent 后自动重建；前端继续通过 `backend` 服务名访问，数据库计数仍在。
- 第二项目不能解析第一项目服务名，也无法直接通过容器 IP 访问其后端；真实 CNI firewall 隔离负面测试通过。
- 应用元数据、密钥元数据与示例应用日志没有出现上传密码。
- 额外使用真实 Web → Go → Rust → containerd 链路，在浏览器停止/启动 PostgreSQL，查看后端健康与实际错误日志；最终安装包升级后四服务继续可用，密钥文件、卷元数据和管理令牌校验保持一致。
- 浏览器回归测试通过真实 Go + Rust API 验证应用诊断、日志纯文本显示、部署/启停、密钥与持久任务流程；浏览器回归中的容器运行时使用测试替身，上述四服务验证使用实际运行时。

四服务稳定后一次整个验证容器观测为约 976 MiB / 2 GiB、CPU 0.29%；其中包含约 805 MiB 的 tmpfs 数据、镜像及文件缓存，不能当作平台进程常驻内存或腾讯云整机容量保证。数据库连接池和缓存均为示例小负载配置。

自动检查：Rust 65 项通过，1 项独立 Linux 测试默认忽略；Go race/跨语言集成、Rust clippy、Web 生产构建、8 项 TypeScript SDK 测试、2 项浏览器测试及 8 项安装器测试通过。

当前边界：HTTP 检查按需执行，网页诊断打开时每 10 秒刷新，不做后台告警和 HTTP 自动重启；不同项目网络隔离不等于恶意多租户的强安全沙箱。AMD64 安装包编译和结构校验与 ARM64 实际节点验收分开记录；没有声称已验证 Tencent VM、GPU、数据库备份恢复或完整系统断电重启。
