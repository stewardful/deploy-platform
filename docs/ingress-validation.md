# 0.4 HTTPS 验收记录

2026-10-18，本地隔离 Ubuntu 24.04 ARM64，systemd、cgroup v2，限制 2 CPU / 2 GiB / 512 PID。未连接腾讯云真实服务器或用户公网域名。

已通过：

- 最终 `.run` 全新安装启动 containerd、独立 Rust Agent、Go/Web 和 DynamicUser Caddy；私有 Unix 管理 Socket 父目录 0700，TCP 2019 未监听。
- 从 0.3 的真实前后端/PostgreSQL/Redis 项目升级到 0.4，修复发布目录遍历权限；最终包再次升级仍保留数据卷元信息、密钥文件、管理令牌和数据库记录。
- 独立本地 ACME CA 执行真实 HTTP-01 挑战，前端与后端取得签名证书；标准 TLS 客户端验证域名、时间、链和测试节点系统信任，HTTPS 读回 SQL/Redis 数据。
- 在隔离测试中加速续期窗口及检查间隔，触发真实 ACME 自动续期，确认新证书已实际用于 HTTPS；生产配置的续期参数没有改变。
- 代理单独重启时从 bootstrap 恢复域名路由，保留证书；Agent 重启及后端容器重建后 HTTPS 恢复，数据仍在。
- HTTP 跳转 HTTPS；SNI/Host 不一致返回 421；过期编辑版本返回 409；应用停止后 HTTPS 503，启动后恢复。
- 最终网页实际操作 Go → Rust → Caddy：绑定域名、查看已签发证书、停用/启用与移除。移除收敛后域名不再代理，其他域名继续可用。
- Rust 69 项测试通过，1 个独立 Linux 测试默认忽略；Go race/Socket 集成及证书验证测试、8 项 TS 测试、3 项浏览器回归、安装器 8 项测试、构建/静态检查通过。

一次完整节点观测约 913 MiB / 2 GiB、CPU 1.11%，包含四个业务服务、两个 Caddy（公共代理及额外测试 CA）、镜像/文件缓存和 tmpfs 数据。它不是平台常驻内存、峰值容量或腾讯云 VM 的资源保证。

本地测试 CA 的根证书只安装在本任务可删除测试容器中；没有向开发电脑或腾讯云服务器添加信任。测试域名仅写入该容器 hosts，特殊 ACME CA 参数仅通过测试节点 root 配置使用，未进入生产安装默认配置。

ARM64 做了上述真实节点验收；AMD64 为二进制编译、ELF 架构、归档和摘要校验。没有把本地 CA 证书说成已从公网 Let's Encrypt 完成实签，也没有声称验证了物理断电/腾讯云服务器重启。

可复用的运行时验收位于 `distribution/tests/https-runtime.py`，需要显式标记的可删除测试节点、已部署四服务项目及本地 ACME 测试 CA。生产使用指南见 [域名与 HTTPS](ingress.md)。
